# Eva integration rollout

## Service wiring

Keep the existing subscription database. Docker Compose now reads MONGODB_URI
from .env rather than silently replacing it with a new local Mongo instance.
Deploy the API and `npm run start:worker` with the same Mongo and Redis settings.
Mongo is the durable queue; Redis dispatches jobs. The worker polls Mongo if
Redis is unavailable. Do not expose Redis publicly.

On the main AI-Companion backend set:

```
SUBSCRIPTIONS_SERVICE_URL=https://YOUR-SUBSCRIPTIONS-HOST
SUBSCRIPTIONS_SERVICE_API_KEY=<same value as SUBSCRIPTIONS_API_KEY>
PAYMENT_CONFIRMATION_TOKEN=<random shared internal secret>
FREE_MESSAGE_LIMIT=10
```

On the subscriptions API and worker set:

```
PAYMENT_CONFIRMATION_URL=https://YOUR-BACKEND-HOST/api/v1/internal/payment-confirmation
PAYMENT_CONFIRMATION_TOKEN=<same random shared internal secret>
PLAN_AMOUNT=49900
PLAN_CURRENCY=INR
FREE_MESSAGE_LIMIT=10
```

The confirmation URL is our backend route. The token is generated by the
operator and shared between these services, not obtained from Google Play.
It authenticates notification delivery, not the purchase. Provider verification
and webhooks determine entitlement independently.

Set frontend API_BASE_URL to the main backend URL including /api/v1. Keep
service keys on servers only. Set MEMORY_SERVICE_URL and MEMORY_SERVICE_API_KEY
on the main backend; use the matching key on the memory service. Profile
metadata is stored in the main conversation database as user_profile_metadata.
Both profile and chat memory sync retry periodically from Mongo.

## Existing database migration

Back up the subscription database and stop API/worker writes. Review the dry
run `node scripts/migrate-billing-indexes.mjs`, then execute with `--apply`.
This replaces three compound sparse unique indexes with partial unique indexes.
Investigate duplicate-key failures before restarting; do not delete user data.
New empty databases use the corrected Mongoose definitions directly.

## Provider setup

Create/verify the monthly INR 499 product and base plan in Play Console and
the equivalent Razorpay recurring plan. Configure service-account permissions,
RTDN delivery, Razorpay credentials and signed webhooks in the subscription
service. Confirm provider-side prices; environment values cannot change them.

Alternative billing approval is pending. Default Android builds have it off.
For an approved/test-eligible build use `-PalternativeBillingEnabled=true` and
set GOOGLE_PLAY_ALTERNATIVE_BILLING_ENABLED=true server-side. The Android
callback supplies Google's externalTransactionToken; the backend retains it
and queues captured-payment reporting. Set correct tax region and tax rate.
Do not publish or enable this flow for users until approval and acceptance tests.

## Acceptance gates

- Two different companions recall the same user's facts; another account cannot.
- Onboarding persists after restart and Mem0 outage/recovery.
- Ten free messages across companions; concurrent message 11 is rejected.
- Play sandbox purchase, restore, acknowledgement, renewal, cancellation,
  expiry, grace period, hold, and duplicate/out-of-order RTDN.
- Razorpay sandbox activation and renewal; duplicate webhook delivery and
  external transaction reporting verified in Google's API.
- Stop Redis and restart workers mid-job; Mongo jobs recover without granting
  duplicate entitlement. Stop callback endpoint; confirmations retry.
- Inspect authenticated GET /api/v1/internal/queue/status; retry failed jobs
  with POST /api/v1/internal/queue/:id/retry after resolving their cause.

This is not a production certification. Live provider acceptance, external
billing refund reconciliation, tax validation, and browser/device end-to-end
tests remain release gates. Do not enable alternative billing before these pass.
